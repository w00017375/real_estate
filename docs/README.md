# Estate parser

## Основные команды

Полный обход всех подключённых источников с записью в SQLite:

```powershell
python main.py
```

Ограниченный запуск — по первым 7 объявлениям каталога каждой платформы:

```powershell
python main.py --limit 7
```

JSON только с выбранных платформ, без чтения и изменения SQLite:

```powershell
python parse_platform.py olx --limit 3
python parse_platform.py etagi uybor realting --limit 5
python parse_platform.py all --limit 3
```

Результаты сохраняются отдельно в `output_json/<platform>/`.

Локальная дедупликация продавцов после парсинга:

```powershell
python seller_deduplication.py --database olx_apartments.db
```

Поиск отсутствующих телефонов на страницах уже сохранённых OLX-объявлений:

```powershell
python -m tools.enrich_olx_listing_phones --database olx_apartments.db
```

Ежедневная ручная проверка актуальности и поиск новых объявлений:

```powershell
python live_scanner.py
```

Скрипт сначала параллельно проверяет все активные URL в базе. Однозначно
удалённые или закрытые публикации получают `publication_status = closed`;
тайм-ауты, CAPTCHA, HTTP 403/429 и ошибки сети статус не меняют. Затем все
площадки сканируются параллельно от новых карточек к старым. Известные
публикации повторно открываются: текущие данные обновляются, а фактические
изменения цены, описания, статуса и характеристик попадают в
`listing_history`.

Тестовый запуск с максимум пятью карточками каждой площадки и
шестью потоками проверки актуальности:

```powershell
python live_scanner.py --new-limit 5 --availability-workers 6
```

Мониторинг только выбранных платформ:

```powershell
python live_scanner.py --platforms olx realt24
```

Без `--new-limit` ограничение количества объявлений не применяется.
Скрипт выполняет один полный цикл и завершается; запускайте эту команду
вручную один раз в день.

## Автономные исходные парсеры

Скрипты без общего запуска находятся в `standalone_parsers`. Запускайте их
как Python-модули из корня проекта, например:

```powershell
python -m standalone_parsers.olx_publication_raw_json "URL"
python -m standalone_parsers.realt24_publications_raw_json
python -m standalone_parsers.uysot_publications_raw_json
```

## Интерактивная карта

Карта читает текущий `olx_apartments.db` без изменения данных:

```powershell
python -m dashboard.server
```

После запуска откройте `http://127.0.0.1:8765`. Автоматическое открытие
браузера отключено; при необходимости используйте `--open`.

Карта объединяет совпавшее жильё из нескольких публикаций в одну карточку,
не учитывая название площадки. В карточке показываются цены по источникам и
предыдущая цена с датой изменения, если цена менялась.

```powershell
python -m dashboard.server --database olx_apartments.db --port 9000
```

### Слой качества воздуха OpenWeather

Ключ хранится только на локальном сервере и не передаётся в JavaScript. Создайте
в корне проекта файл `.env` на основе `.env.example`:

```text
OPENWEATHER_API_KEY=ваш_ключ
```

После запуска карты включите switch **«Качество воздуха»** под выбором территории.
Ответ OpenWeather кэшируется на один час в `dashboard/.cache/openweather_tashkent.json`, поэтому
перезагрузка страницы и несколько открытых вкладок не создают новые внешние
запросы. Скрипт ведёт собственный месячный счётчик и прекращает обращения на
9 000 запросах. Это локальный защитный предел, а не квота всего аккаунта OpenWeather.

API Air Pollution возвращает индекс OpenWeather по координатам в шкале **1–5**.
Карта ежечасно запрашивает оценку в центрах 12 районов Ташкента и показывает
цифры и тепловой слой по этим точкам. Это **модельные координатные оценки, а не
замеры физических станций**. За 31 день при таком режиме получится не более
8 928 обращений, если не учитывать дополнительные ручные запросы вне карты.

## Служебные файлы

- `docs/` — документация, UML и матрица источников;
- `backups/` — резервные копии SQLite;
- `tools/` — локальные миграции и генераторы артефактов;
- `output_json/` — JSON, разложенный по платформам;
- `standalone_parsers/` — автономные парсеры отдельных сайтов.
